# Security reporting

This policy covers Phantom-plugins, independently maintained by [newkayak12](https://github.com/newkayak12). It does not represent JetBrains or promise access to an upstream vendor's response program.

Do not post exploit details, credentials, private project data or working attacks in public issues, pull requests or discussions. Use a private contact method explicitly published on the [maintainer's profile](https://github.com/newkayak12). If no private channel is listed, ask for a private reporting channel without disclosing the vulnerability. A repository's private visibility is not a substitute for a designated security reporting channel.

Provide the affected version or commit, impact, minimal reproduction using your own data, and any suggested mitigation through the agreed private channel. Limit testing to systems and data you control; do not disrupt services or access other people's data. Coordinate public disclosure with the maintainer.

There is no guaranteed response time, supported-version window or bug bounty. Fixes and release timing depend on maintainer availability. For a vulnerability in an upstream dependency, use that project's published security policy as well; do not assume this project's maintainer can resolve it.

Upstream legal attribution remains in LICENSE, NOTICE and plugin-specific notices.
