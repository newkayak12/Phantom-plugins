# Phantom Local Shared Index 변경 이력

## 미배포

- 같은 컴퓨터의 다른 체크아웃이 이미 인덱싱한 파일은 내용 전용 인덱스(IdIndex, Trigram, Java 식 인덱스, Kotlin 소스 이름 인덱스)를 아예 다시 만들지 않고, 조회할 때 그 체크아웃 파일의 데이터를 쓴다. git으로 받은 파일은 git 인덱스의 blob id로 찾아 파일을 읽지 않는다. 새 클론에서 인덱싱 시간이 절반 이하로 줄었다. 레지스트리 `phantom.localsharedindex.alias`로 끌 수 있다.

## 0.1.1 (2026-11-20)

- 캐시 키 맵의 메모리를 줄였다. 키마다 객체 4개(맵 노드, 키, 키 배열, 위치)를 두던 ConcurrentHashMap 대신 키 지문과 위치를 long 배열에 담는다. 키 114만 개인 프로젝트에서 GC 후 heap이 320MB에서 244MB로, 프로세스 메모리(footprint)가 1,358MB에서 1,233MB로 줄었다(3회 중앙값). 시작·인덱싱 시간은 측정 오차 안에서 같다. 지문이 겹치면 디스크 레코드의 키 비교로 캐시 미스가 될 뿐 잘못된 값은 나오지 않는다.

## 0.1.0 (2026-11-19)

- 같은 컴퓨터에서 같은 프로젝트의 다른 체크아웃(워크트리, 클론)이 이미 인덱싱한 파일은 다시 인덱싱하지 않고 인덱스 데이터를 재사용한다. 파일 내용만으로 결과가 정해지는 인덱스(IdIndex, Java 식 인덱스, Trigram, Kotlin 소스 이름 인덱스)와 스텁(Java, 클래스 파일, Kotlin .kt)만 대상이다. (#30)
- 같은 파일 내용을 이미 인덱싱한 다른 체크아웃이 있으면 IdIndex와 Java 식 인덱스 데이터를 다시 계산하지 않고 재사용한다. 저장하지 않은 편집은 캐시를 거치지 않는다. (#30)
- 같은 파일 내용을 이미 인덱싱한 다른 체크아웃이 있으면 Java 스텁을 다시 만들지 않고 재사용한다. (#30)
- 같은 파일 내용을 이미 인덱싱한 다른 체크아웃이 있으면 Kotlin(.kt) 스텁도 다시 만들지 않고 재사용한다. 스크립트(.kts)는 제외한다. (#30)
- 캐시 크기 한도를 고급 설정(기본 2GB)에서 바꿀 수 있다. 캐시가 손상되거나 인덱스가 초기화돼도 직접 지울 필요 없이 복구하고, 다른 IDE가 캐시를 쓰는 중이면 캐시 없이 동작한다. (#30)
- 프로젝트 인덱싱이 끝날 때마다 캐시에서 가져온 비율과 절약한 시간을 로그 한 줄로 남긴다. 레지스트리 키 phantom.localsharedindex.verify.one.in으로 캐시 적중을 다시 계산해 검증할 수 있고, 다르면 해당 인덱스는 재시작 전까지 캐시를 쓰지 않는다. (#30)
