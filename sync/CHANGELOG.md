# Phantom Settings Repository 변경 이력

## 미배포

## 0.1.3 (2026-11-27)

- 저장소 URL에 비밀번호나 토큰(`https://user:TOKEN@host/...`)을 넣으면 연결을 거부한다. URL은 평문으로 저장되므로 SSH 키나 credential helper를 쓴다. (#PR)
- 작업 사본을 depth 1로 받아 동기화 기록이 쌓여도 로컬 사본이 커지지 않는다. 원격 저장소의 기록은 그대로 남는다. 파일 버전이 커밋 해시 대신 내용 해시가 되어, 업데이트 직후 한 번 설정을 다시 받을 수 있다. (#PR)
- 같은 저장소를 쓰는 여러 동기화 작업이 한 작업 사본에서 git을 동시에 실행하지 않는다. (#PR)

## 0.1.2 (2026-11-26)

- 원격 브랜치가 마지막으로 받은 커밋 그대로면 설정 확인 때 `git fetch`를 다시 하지 않는다. 확인과 읽기마다 원격에 두 번 접속하던 것이 `ls-remote` 한 번으로 줄어든다. (#121)

## 0.1.1

- 두 기기가 거의 동시에 올릴 때 한쪽 설정이 조용히 덮어써지지 않는다. 버전을 확인한 원격 커밋 위에 커밋하므로, 그 사이 다른 기기가 올렸으면 push가 거부되고 다시 받아 버전을 확인한다.
- 저장소 URL에 넣은 토큰·비밀번호(`https://user:TOKEN@host/...`)를 idea.log와 오류 메시지, 계정 이름 표시에서 `***`로 가린다. git이 stderr에 찍는 URL도 가린다.
- git이나 ssh가 출력을 연 채 멈춰도 제한 시간(120초)이 지나면 프로세스와 그 자식 프로세스를 끝내고 시간 초과 오류를 낸다.
- git이 끝난 뒤 남은 자식 프로세스가 출력을 붙잡고 있어도 기다림이 끝없이 이어지지 않는다 (2초 뒤 읽은 만큼만 쓴다).

- Phantom 저장소의 `plugins/phantom-sync`에서 옮겨 와 이 저장소에서 빌드한다. id(`dev.phantom.sync`)와 동작은 그대로다 (#39).
