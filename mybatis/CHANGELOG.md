# Support for MyBatis 변경 이력

## 미배포

## 0.3.6 (2026-11-27)

- 구현으로 이동이 `BaseMapper<T>` 같은 상위 인터페이스에서 물려받은 메서드에서도 하위 매퍼의 XML statement를 연다. (#175)
- 라이브러리 jar에 들어 있는 매퍼 XML도 찾는다. (#175)
- 다른 매퍼 파일의 `<sql>`을 `<include>`한 statement에서, 그 파일을 고친 뒤에도 옛 조각이 SQL 하이라이팅에 남던 문제를 고쳤다. 다른 파일의 조각은 주입된 SQL에 복사하지 않고 문법 검사에서만 읽는다. (#175)
- 다른 파일 조각을 찾는 SQL 문법 검사가 인덱싱 중에는 돌지 않는다. (#175)
- 큰 매퍼 XML의 검사가 빨라졌다: 중복 id 검사가 태그마다 파일 전체를 다시 훑지 않고, 문법 검사·namespace 클래스·bean 속성 결과를 캐시한다. MyBatis가 없는 모듈의 인터페이스는 인덱스를 묻지 않는다. (#175)
- statement 추가 quick fix가 읽기 전용인 매퍼 XML을 먼저 쓰기 가능하게 해 달라고 묻는다. (#175)

## 0.3.5 (2026-11-26)

- 표시 이름을 바꿨다: Phantom for MyBatis → Support for MyBatis. 플러그인 id와 기능은 그대로다. (#136)

## 0.3.4 (2026-11-24)

- 매퍼 인터페이스의 XML 파일 찾기가 다른 Java·Kotlin 파일을 입력할 때마다 다시 하지 않는다. 그 인터페이스 파일, XML 파일, 파일 추가·삭제가 있을 때만 다시 찾는다. (#128)
- 매퍼 인터페이스의 XML 파일 찾기를 PSI가 바뀔 때까지 캐시해서, 거터 아이콘과 검사가 메서드마다 인덱스를 다시 조회하지 않는다. MyBatis가 없는 프로젝트의 인터페이스 편집도 가벼워진다. (#120)

## 0.3.3 (2026-11-22)

- 이름을 바꿨다: MyBatis Support → Phantom for MyBatis. Phantom으로 시작하고, 지원하는 프로젝트 이름은 뒤에 둔다. 플러그인 id와 기능은 그대로다.

## 0.3.2 (2026-11-20)

- 플러그인 jar에 `LICENSE`, `NOTICE`와 서드파티 라이선스 고지를 넣었다. (#45)
