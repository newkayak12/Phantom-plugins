# Phantom Database Console

`dev.phantom.db` · [한국어](./KOR.md)

A JDBC console for MySQL, MariaDB, PostgreSQL, H2, AWS, Oracle, SQL Server and more, with drivers you can add.

- `.sql` files get highlighting, brace matching, comments and keyword completion.
- **Ctrl+Enter** runs the statement at the caret; the gutter has a run icon per statement.
- Results open in a sortable grid; long queries can be cancelled.
- The **Database** tool window shows data sources and a schema tree that loads one level at a time.
- **Drivers are data.** 14 presets (MySQL, MariaDB, PostgreSQL, H2, AWS JDBC Wrapper for MySQL and PostgreSQL, AWS JDBC Driver for MySQL (`jdbc:mysql:aws:`), Amazon Redshift, Amazon Athena, Oracle, SQL Server, SQLite, ClickHouse, Snowflake) plus your own. The **Drivers…** dialog (tool window, or **Configure Drivers…** from an error) adds, duplicates, removes and resets drivers: jar files or Maven coordinates, version (`LATEST` is pinned at download; **Check for updates**), URL template, URL prefixes, default properties, dialect and extra Maven repositories (Maven Central is always first). The driver class is detected from the jars.
- **Where the jars come from**, in order: jars you chose, the driver's own files, project libraries, local Gradle/Maven caches, then downloaded jars (kept in the IDE system directory). Existing MySQL, MariaDB, PostgreSQL and H2 setups keep working with no download.
- **Downloads happen only on request**: **Download**, **Test Connection**, or the notification's **Download driver**. Transitive dependencies are resolved and SHA-1 is checked.
- The data source dialog has a driver combo (pasting a URL selects the driver), host/port/database fields or a raw URL, and authentication: user/password, none, or **AWS IAM** (AWS profile and region, handled by the driver's own IAM support). A driver properties table is included.
- **Databases without SQL intelligence** (dialect "Other": Redshift, Athena, Oracle, SQL Server, SQLite, ClickHouse and Snowflake by default): the console, result grid, schema tree and export work; dialect checks, EXPLAIN, DDL, table modify, schema compare and grid editing are off.
- Vendor icons mark drivers and data sources.
- **Team sharing**: data sources still store `dbms` for 0.10.0 readers. A driver id unknown on a teammate's IDE falls back by URL prefix, else shows a "not defined" error with **Configure Drivers…**.
- **Manual commit** (a data source setting): statements run in an open transaction. The **Database Changes** tool window lists what is in it, with **Commit** and **Roll Back**; `COMMIT`/`ROLLBACK` typed in the console work too, and closing the project asks first.
- **Edit in the grid**: a result from one table that includes its primary key can be edited in place. A changed cell runs an `UPDATE` by key, deleted rows a `DELETE`; Add Row and Clone Row open an `INSERT` in the console to finish. On a manual-commit data source the edits wait in Database Changes.
- **Compare With…** on a schema: the diff viewer shows tables, columns, keys and indexes of two schemas (any data sources), and opens the SQL that makes the other one match in its console. Drops are written commented out.
- **Data source colors** (as in DataGrip): pick a color in the data source dialog. Its consoles and `.sql` files get it as editor background and tab color, its rows in the Database tree a tint, its result tabs a stripe. Saving the data source recolors them right away. The color is saved with the data source, so the team shares it.
- **Schema per console**: **Schema: …** above a console or `.sql` file (or **Choose Schema…** in the editor menu) picks the schema it runs in, the catalog for MySQL and MariaDB. Statements run there, and unqualified table names in completion, navigation and checks resolve there first. The choice is kept per file.
- **Explorer** (as in DataGrip): each schema groups its objects in folders: tables, views, materialized views (when the driver reports them), routines, triggers and sequences; each table its columns (type, PK, FK, NOT NULL), keys, foreign keys, indexes and triggers. Folders load when expanded and stay cached until **Refresh**. Double-click or **F4** opens a table's data, the DDL of a view, routine or trigger, or the table a foreign key references. Type in the tree to jump (speed search); the filter field above it narrows loaded objects by name and hides empty folders. **Show System Schemas** in the toolbar adds `information_schema`, `pg_catalog` and the like.
- **Navigate → Database Object…** (also a **Database** tab in Search Everywhere) finds tables, views, routines and columns the tree has loaded in any data source, with data source and schema beside each; it never connects. Choosing one selects it in the tree and opens its data or DDL.
- **New Console** (tree, toolbar, Tools menu; **Ctrl+Shift+Q** or **Ctrl+Alt+Shift+Q**, **Cmd+Shift+L** or **Ctrl+Cmd+N** on macOS) opens another console of the selected data source in the selected schema: `<name>.sql`, `<name> [1].sql`, … in Scratches and Consoles → Database Consoles. They are listed in the data source's **consoles** folder and in **Navigate → Jump to Console…**. A data source's consoles share its console connection, so a manual-commit transaction (and Database Changes) is one per data source, not per console.
- **JOIN completion** (as in DataGrip): after `JOIN`, the tables a foreign key links (either way) to a table already in FROM come first, each with its alias and `ON` clause (`customer c ON o.customer_id = c.id`). After `JOIN t [alias] ON`, whole conditions joining `t` to every table before it: from foreign keys first, then guesses by column name (`x_id` = `x.id`, the same `*_id` column on both sides). Only cached metadata is read; missing keys load in the background and appear on the next keystroke.
- **Live templates** in the **SQL (Phantom)** group, in `.sql` files, consoles and SQL strings: `sel`, `selc` (count), `selw` (WHERE), `ins` (fills the column list when the table's columns are loaded), `upd`, `del`, `crt`. The table name completes.
- **Find Usages and Rename** of tables, views and columns: usages in `.sql` files, consoles and SQL strings in Java and Kotlin (`@Query`, JdbcTemplate, JdbcClient) that resolve to the same table or column, plus JPA `@Table` / `@Column` / `@JoinColumn` names. Rename changes the SQL text only (quoted names keep their quotes, unquoted ones their case) and never the database; the dialog can also write `ALTER … RENAME` into the data source's console without running it, and rename the JPA mappings. Both are off by default.
- **Unknown table / Unknown column** inspections (once the schema is loaded) with quick fixes: add the missing alias to a table, qualify a column with the table that has it. **SELECT \* in SQL strings in code** (off by default) can list the columns instead.
- **SSH/SSL** tab of a data source: an **SSH tunnel** (host, port, user; password, private key file with passphrase, or the running OpenSSH agent) forwards `127.0.0.1:<free port>` to the URL's host and port, or to an explicit remote host and port for URLs without one. One tunnel per data source, shared by its connections and closed with them; **Test Connection** opens one of its own. An unknown host key is shown with its SHA256 fingerprint and, once accepted, added to `~/.ssh/known_hosts`; a changed key is refused. **SSL**: on/off, mode (require, verify CA, verify CA and host name) and CA, client certificate and key files, written as each built-in driver's own properties (MySQL `sslMode`, PostgreSQL `sslmode`/`sslrootcert`, SQL Server `encrypt`/`trustServerCertificate`, …); other drivers use the Properties table, which always wins.
- **Diagram** (tree toolbar or context menu, on a schema or selected tables) opens an editor tab with the tables and their columns (PK and FK marked), foreign keys as lines, laid out in layers along the keys. Drag to pan or move a table, wheel to zoom, **Export as PNG**. Up to 200 tables.
- **Import Data from CSV…** on a table: delimiter, quote and header are guessed and can be changed, the first 50 rows are previewed, and each column is filled from a CSV column (by header name, else position) or left out. The rows go in with batched INSERTs in one transaction in the background (cancellable); a bad row rolls the whole import back and names its line. In a manual-commit data source the rows join the open transaction and wait in Database Changes.
- **Copy Table To…** on a table copies its rows into a table of the same name in another schema of the same or another data source (DataGrip's data transfer for one table): a missing table is created with the columns and primary key (types translated between databases), an existing one gets the columns both have, by name; the rows go page by page in batches, in the background, and a manual-commit target keeps them until Commit.
- **Explain Plan / Explain Analyze** show the plan as a tree with cost, rows and time, the costliest step in red, and the text form in a second tab (PostgreSQL and MySQL/MariaDB plans are read as JSON, MySQL's EXPLAIN ANALYZE tree and H2's text by indentation).
- **Results grid**: a table's data view (and a select from one table) has **WHERE** and **ORDER BY** fields that are small SQL editors completing the table's columns; Enter runs from the first page, the drop-down lists earlier filters of that table, and a filtered select keeps its own WHERE. In a table's data view a click on a column header sorts on the server (ORDER BY the column, then descending, then none). The status line shows **Transpose** (records as columns), the **Value Viewer** (the selected cell in full next to the grid: wrapped text, pretty-printed JSON, XML, bytes as a hex dump with Save to File, PNG/JPEG as a picture; a text cell of an editable result can be changed there) and, for a selection, count, distinct, sum, average, minimum and maximum. **Copy As** (grid popup or status line) copies the selection as TSV, CSV, JSON, SQL INSERT (into the edited table, else asked), SQL INSERT Multirow, SQL UPDATE (by the primary key, else every column), One-Row (the values as SQL literals on one line, for an IN list), Markdown, HTML, XML or Pretty (a text table); the same formats are in the grid's **Data Extractor** list, and Copy (Cmd/Ctrl+C) copies in the one chosen there, as in DataGrip. Paste (Cmd/Ctrl+V) of copied rows fills the cells from the selected one and adds rows as needed, the text taking each column's type (numbers, booleans, dates and times); **Filter by** on a cell adds `= value`, `<> value`, `LIKE '%value%'`, `IS NULL` or, for several cells of a column, `IN (…)` to the WHERE field (with AND) and runs it; **Column Statistics** shows the selected column's NULLs, distinct values, sum, average, minimum, maximum and most frequent values in the rows shown; **Export…** saves or copies the shown rows in those formats, and in a table's data view writes the whole table (with its filter and order) to a file page by page in the background. A run replaces its console's result tab, titled with the first SQL line, unless the tab is pinned; the gear menu has Pin Tab, Close Other Tabs and Close All Tabs.
- Passwords (also SSH passwords and key passphrases) go to the IDE password safe, never to the project files. As in DataGrip, **Save:** next to the password keeps it **Forever** (password safe), **Until restart** (memory only) or **Never**; the password safe is read once per IDE run, so the OS keychain is not asked at every connection. A refused sign-in (or a "Never" password) asks for the user and password and retries.
- **Shortcuts as in DataGrip**: every Database tree command is in the keymap (Settings → Keymap → Plug-ins → Phantom Database). In the tree: **Cmd+N**/**Alt+Insert** add a data source, **Cmd+I**/**Shift+Enter** edit it, **Delete** removes it, **Cmd+R**/**Ctrl+F5** refreshes, **Cmd+B**/**Ctrl+B** shows the DDL, **Cmd+F6**/**Ctrl+F6** modifies the table, **Cmd+D**/**Ctrl+D** compares schemas, **Cmd+Alt+Shift+U**/**Ctrl+Alt+Shift+U** opens the diagram. In a console: **Cmd+F2**/**Ctrl+F2** cancels the running statement, **Cmd+Alt+Shift+Enter**/**Ctrl+Alt+Shift+Enter** commits, Console.Open's keys jump to a console.
- **Groups, Copy / Paste, Duplicate** (as in DataGrip): **Move to Group…** (F6) puts a data source in a folder of the tree (`a/b` nests; on a folder it renames it); **Copy**/**Paste** carries data sources as XML to another project or IDE (passwords stay behind), **Duplicate** (Cmd+D) copies one with a new id.
- **SQL Generator…** (Ctrl+Alt+G) opens a table's DDL with a SELECT, INSERT, UPDATE and DELETE of its columns keyed by the primary key; **Copy DDL** (Ctrl+Shift+C / Ctrl+Alt+Shift+G) copies the DDL; **Select in Database View** (Alt+Shift+B) in a `.sql` file or console selects the table or column at the caret, else the data source, in the tree.
- **Set NULL** (Ctrl+Alt+N) and **Set DEFAULT** (Ctrl+Alt+D) in an editable grid; Set DEFAULT reads the value the database put there back into the cell.
- **Submit** (as in DataGrip): edited cells and deleted rows are shown as changes until **Submit** (Cmd/Ctrl+Enter) runs them, updates first; **Submit and Commit** (Cmd/Ctrl+Alt+Shift+Enter) then commits a manual-commit transaction; **Revert Selected** (Ctrl+Alt+Z) drops the selected changes, **Preview Pending Changes** shows the statements Submit would run. **Add Row** (Alt+Insert / Cmd+N) and **Clone Row** (Cmd/Ctrl+D) add rows in the grid, filled in place and inserted on Submit (empty columns take their defaults). **Submit Changes Immediately** in the grid's popup writes each edit as it is made. Also in the grid: **Select Row** (Shift+Space), **Select Column** (Ctrl+Space), **Edit Filter Criteria** (Ctrl+Alt+Shift+F) and **Edit Ordering** put the caret in the WHERE / ORDER BY field.
- **SSH password or key passphrase** missing or refused: asked at connect (with **Save**), and the tunnel tries again.
- **Sessions** (as in DataGrip): a connected data source has a green dot in the tree; **Disconnect** (Cmd+F2 / Ctrl+F2 in the tree) closes its connections, **Sessions…** lists the open ones (shared console connection, a console's own, the schema tree's; since when, open transaction) to close one or all. **Single session mode** (data source dialog, on by default) shares one connection among the consoles; off, each console gets its own. Manual commit always shares one. With single session mode off, **Session:** above a console (or **Choose Session…** in its popup) runs it in its own session, the shared one, another console's, or a new named one. The **Services** tool window has a **Database** node with the connected data sources and their sessions (Disconnect, Close Session).
- **Schemas** (data source dialog, Options): which schemas (catalogs in MySQL) the tree, completion and checks load, as names or globs separated by commas (`app, sales_*`), `!name` to leave one out; empty loads all. **Introspection level**: 1 names only (no columns or keys looked up for completion and checks), 2 a table's columns and keys when it is used (the default), 3 every table's columns loaded with the schema.
- **Make Global** (Database tree, on a data source) moves it to the IDE so every project lists it, with its password; **Move to Project** takes it back. Global data sources are marked *global* in the tree.
- Nothing runs at startup; the plugin loads its code when a `.sql` file or the tool window opens.

Phantom suggests this plugin when a project depends on the JDBC driver of any preset.
