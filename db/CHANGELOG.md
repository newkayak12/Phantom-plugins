# Phantom Database Console 변경 이력

## 미배포

## 0.25.12 (2026-11-26)

- 접속할 때 묻는 데이터베이스·SSH 비밀번호를 EDT가 아닌 백그라운드 스레드에서 비밀번호 저장소(OS 키체인)에 저장해, 키체인이 응답을 기다리는 동안 IDE가 멈추지 않는다. (#115)
- Database 도구 창 아이콘을 표 대신 데이터베이스 원통으로, Database Changes 아이콘을 변경 목록 대신 시계가 붙은 원통(커밋 대기)으로 바꿨다. JPA의 Entity Diagram과 더는 같지 않다. (#112)

## 0.25.11 (2026-11-22)

- PostgreSQL 복원 확인창이 선택한 스키마 대신 실제 대상(호스트:포트/데이터베이스)을 보여 주고, 파일 전체가 실행되어 선택한 스키마로 제한되지 않는다고 알린다. (#65)
- 덤프를 같은 폴더의 임시 파일에 먼저 쓰고 성공했을 때만 대상 파일을 바꾼다. 실패하거나 취소해도 덮어쓰려던 기존 백업이 그대로 남는다. (#65)
- MySQL·MariaDB에서 데이터베이스를 고르지 않은 덤프(`--all-databases`)는 대상 서버를 보여 주고 먼저 묻는다. (#65)
- Query History가 비밀번호를 담은 문장(ALTER USER … PASSWORD, IDENTIFIED BY, SET PASSWORD 등)을 저장하지 않는다. 데이터 소스마다 히스토리를 끌 수 있고, 끄면 그 데이터 소스의 기록을 지운다. Find Action에서 Clear Query History로 전체 기록을 지울 수 있다. (#65)
- 저장소가 SHA-1 체크섬을 주지 않는 드라이버 jar는 설치하지 않는다(경고만 남기고 설치하던 동작을 바꿈). 받아 둔 jar는 설치할 때 기록한 다이제스트와 같을 때만 다시 쓰고, 다르면 새로 받는다. (#65)

## 0.25.10 (2026-11-22)

- 입력할 때 CPU를 덜 쓴다. JPA 스키마 검사가 Java·Kotlin 파일을 칠 때마다 Spring 설정 파일을 다시 읽지 않고, SQL `CREATE TABLE`의 엔티티 표시가 SQL을 칠 때마다 엔티티를 다시 찾지 않는다. 결과는 그대로다.

## 0.25.9 (2026-11-20)

- 플러그인 jar에 `LICENSE`, `NOTICE`와 서드파티 라이선스 고지를 넣었다. (#45)
