# Support for OpenAPI 변경 이력

## 미배포

## 0.2.6 (2026-11-28)

- 고스트 모드에서는 `$ref`·스펙 모양 검사와 스펙과 핸들러 사이 거터 아이콘을 끈다. `$ref` 이동, 완성, 이름 바꾸기는 그대로다. (#PR)

## 0.2.5 (2026-11-27)

- 스키마나 파일 이름을 바꾸면 `$ref`의 마지막 조각만 새 이름으로 바뀐다. 전에는 `#/components/schemas/Pet` 전체가 새 이름 하나로 덮어써졌다. `~`와 `/`는 `~0`, `~1`로 적는다. (#171)
- 스펙이 `$ref`로 가리키는 다른 파일(나눠 둔 스펙 조각) 안의 `$ref`도 Ctrl+B로 이동하고, 가리키는 대상이 없으면 오류로 표시한다. (#171)
- 스펙과 핸들러 경로 맞추기가 정확해졌다. `/{id}`처럼 파라미터만 있는 경로나 파라미터가 낀 앞부분은 기본 경로로 보지 않고, 경로가 그대로 같은 쪽이 있으면 그쪽만 보여 준다. (#171)
- 핸들러 거터가 핸들러마다 전체 엔드포인트와 operation 목록을 다시 훑지 않는다. (#171)

## 0.2.4 (2026-11-26)

- 표시 이름을 바꿨다: Phantom for OpenAPI → Support for OpenAPI. 플러그인 id와 기능은 그대로다. (#136)
- 핸들러 메서드의 스펙 거터가 엔드포인트 목록을 YAML·JSON 입력마다 다시 찾지 않는다. 각 엔드포인트 제공자의 변경 추적을 따르고, 애너테이션이 없는 파일에서는 제공자를 묻지 않는다. (#119)

## 0.2.3 (2026-11-22)

- 이름을 바꿨다: OpenAPI Support → Phantom for OpenAPI. Phantom으로 시작하고, 지원하는 프로젝트 이름은 뒤에 둔다. 플러그인 id와 기능은 그대로다.

## 0.2.2

- 입력 중 CPU를 덜 쓴다. Java나 Kotlin을 고쳐도 프로젝트의 YAML/JSON 파일을 다시 훑지 않는다. 결과는 그대로다.

## 0.2.1 (2026-11-20)

- 플러그인 jar에 `LICENSE`, `NOTICE`와 서드파티 라이선스 고지를 넣었다. (#45)
